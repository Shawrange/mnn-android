## 1. 输入分组、scale与INT8规则

记F16/F32为对应IEEE格式的舍入，RN为最近偶数舍入（实测FPCR=0），RA为最近整数、恰好半值远离零。

输入在Runtime是NC8物理布局`[128, Token数, 8]`的FP16，Host统一为`[Token数,1024]` float32。源输入来自C2 Low Norm，所有值均可精确表示为FP16，故本轮Host→Low不会增加第一次输入舍入差异。

每个Token t对全部1024通道取 `m[t]=max_k(abs(x16[t,k]))`。一组覆盖整个Token，不是每64通道一组；每64通道是**权重**分组。相关代码：`BatchSymDynamicQuant`，[ConvInt8TiledExecutor.cpp](evidence/source/source/backend/cpu/compute/ConvInt8TiledExecutor.cpp) L2370–2404；`MNNAbsMaxFP16`，[Arm82Functions.cpp](evidence/source/source/backend/arm82/Arm82Functions.cpp) L2692–2727，pack8分支进入[MNNAbsMaxFP16_pack8.S](evidence/source/source/backend/arm82/asm/arm64/low_memory/MNNAbsMaxFP16_pack8.S)。

`MNNQuantScaleFP16`的真实汇编：[MNNQuantScaleFP16.S](evidence/source/source/backend/arm82/asm/arm64/low_memory/MNNQuantScaleFP16.S) L18–25、TILE_12/TILE_8/TILE_1各段（约L75–106、L209–236、L262–281）：先将half absmax提升为float32，用FP32 fdiv得到

```
Q[t] = RN32(127 / m[t])
D[t] = RN32(m[t] / 127)
```

源码对m≤0用127替换，因此全零组得到Q=D=1；本轮没有全零、非有限或极端溢出输入，不宣称覆盖这些边界。

`MNNDynamicQuantFP16`按pack=8调用实际汇编：[MNNDynamicQuantFP16_Pack8.S](evidence/source/source/backend/arm82/asm/arm64/low_memory/MNNDynamicQuantFP16_Pack8.S) L14–18、L24起、TILE_8约L516–578、TILE_1 L698–724。

```
Q16[t]  = RN16(Q[t])             // fcvtn：scale先转half
p16[t,k]= RN16(x16[t,k]*Q16[t]) // fmul .8h：乘法先舍入half
q[t,k]  = sat_int8(RA(p16[t,k])) // fcvtas .8h，再sqxtn
```

RA不是ties-to-even，更不是向零截断；sqxtn饱和范围[-128,127]。本次q实际范围为[-127,113]及[-127,127]，没有需要饱和的越界值。zero-point=0、bias参数nullptr；ARM路径没有x86的+128无符号输入偏移。scale仍以FP32传给后续反量化，不能用1/Q16替代实测D。

## 2. 原量化权重与元数据

原模型q_proj：OC2048、IC1024、1×1；external `[8192,1048598,262144,0,0]`。从同一原权重文件offset8192读取1048598字节压缩权重，其后262144字节FP32 alpha；没有外置或内置Bias。本轮独立提取器仅解析公开FlatBuffer并原样复制字节，不链接MNN数值加载器。

权重header：维数1字节=2、两个uint16小端尺寸2048/1024、sample_count1字节=16、16个有符号样本[-8,…,7]，共22字节。之后1048576字节每字节两值，高nibble先、低nibble后，按[oc,ic]排列。独立解码qSigned∈[-8,7]；Runtime保留qUnsigned=qSigned+8∈[0,15]的packed INT4，用于实际GEMM。

Alpha为`[2048,16,2]`，每输出通道、每64输入通道一对`[z,s]`：

```
W[o,k] = qSigned[o,k] * s[o,k/64] + z[o,k/64]
```

readType=32768非零表示asymmetric，aMin=1不触发loader的负clampMin折叠，quantScale=1、scaleStorage=FP32、has_scaleInt=false。不能把其他模型的alpha约定代入。

源码：`IDSTDecoder::ReadBlobDim/ReadQuanData_c`，[ConvolutionCommon.cpp](evidence/source/source/core/ConvolutionCommon.cpp) L26–48、231–305；`ConvolutionCommon::load` L611–673、795–882。原始packed与Runtime load阶段decoded_weight逐字节相同，alpha也逐字节相同；独立程序又解包为signed int8供主机复算。

CPU准备metadata时对unsigned INT4的零点修正：`zPrepared = RN32(z + RN32(-8*s))`，s保持FP32。见`_computeReorderQuantInfo`，[ConvInt8TiledExecutor.cpp](evidence/source/source/backend/cpu/compute/ConvInt8TiledExecutor.cpp) L281–329；`packWeightAndQuantInfo` L249–278。实测mode0，packed布局每OC8/权重block为256字节INT4权重+8个float scale+8个float offset，总320字节。所有prepared scale/offset与独立重建逐元素精确一致。未走FP16磁盘alpha/紧凑metadata分支。

## 3. 整数GEMM及输出

对每Token t、输出o、权重block b（64通道）：

```
I[t,o,b] = sum_{k in b} q[t,k] * qUnsigned[o,k] // signed INT8 × 0..15，INT32
J[t,b]   = sum_{k in b} q[t,k]                 // INT32
S[t,b]   = RN32(J[t,b] * D[t])
```

独立复算保留I、J为i32文件。实测I范围[-2682,2106]及[-4730,5099]；64×128×15=122880的绝对上界也远低于INT32溢出。本轮不涉及长通道未分块的大整数溢出风险。

SumByAxis实际汇编：[MNNPackC4Int8ForMatMulA_ARM86.S](evidence/source/source/backend/cpu/arm/arm64/MNNPackC4Int8ForMatMulA_ARM86.S) L26起，INT32求和/scvtf/fmul见L111–133、194–212、259–272、317–329、372–386。

GEMM真实实现：[MNNGemmInt8AddBiasScale_ARMV86_w4_Unit_FP16.S](evidence/source/source/backend/arm82/asm/arm64/low_memory/MNNGemmInt8AddBiasScale_ARMV86_w4_Unit_FP16.S) L134–180签名/后处理ABI、L219–278 smmla/unsigned nibble解包、L279–331乘scale/输入scale/offset修正、L362–417跨block累加与Bias/FP16输出。非单Token尾部的一般链：

```
p = RN32(RN32(float(I)*s) * D)
v = FMA32(zPrepared, S, p)
acc = RN32(v + accPrevious)
```

**TILE_1不同**，同文件L1046–1097（不是照抄一般INT8公式）：

```
scaleEff = RN32(s*D)
acc = FMA32(float(I), scaleEff, accPrevious)
acc = FMA32(zPrepared, S, acc)
```

8 Token走TILE_8；13 Token按DST_XUNIT=10先10，再2+1，最后第12号Token走TILE_1。首block的acc显式置零，随后读取同一OC块累加缓冲；不能沿用上一OC块的残留值。参考程序明确模拟两种累加顺序。

最终在FP32中加同一Bias（本模型为正零），fcvtn到FP16，再按实测half阈值[-65504,+65504]夹紧；本轮输出不触发夹紧。没有额外ReLU/激活、输入bias或INT8输出量化。见同文件L390–417及L1107–1121。Host通过Tensor拷贝将FP16/NC8转换为逻辑NCHW float32。

## 独立性与适用边界

[reference.cpp](scripts/reference.cpp)只用标准C++数学/文件接口，编译时不链接MNN，`-ffp-contract=off`确保普通乘加不自动融合，显式std::fma模拟真实FMA。A用FP64解码权重计算；B重建输入INT8、INT32 block dot、真实FP32后处理及FP16输出。FP64参照仍基于相同量化权重，绝不是HF未量化模型黄金输出。

契约与精确复现仅针对本次固定模型、两个输入、当前ARMV86 w4 FP16/mode0路径。没有覆盖ARM82、compact metadata、不同dynamic_option、激活块量化、其他层或更广泛任务质量。不把本次A结论扩展为所有配置都无Bug。
